Recorded on 2026-09-25 in Africa/Johannesburg time. Branch `claude/preview-agent-handoff-8qqer6`, from `master` at `783ef7f`.

## Request

Check what remained from the match-previews handoff (`2026-09-25_10-11-21_match-previews.md`). Then, per the user: leave staging aside (production only), the Vercel plan is Pro, and the agent should run only the first time both teamsheets of a fixture are available, not every two hours.

## Decisions

| Ref | Decision |
| --- | --- |
| T1 | A fixture gets one preview, written once both teamsheets are published. Changed teamsheets and the last hours before kickoff no longer trigger a rewrite. |
| T2 | Nothing polls teamsheets in the background; the API fetches them on request and caches them (20 minutes before publication). The agent's schedule is the timer, but it is now a code handler with no model call, every 15 minutes (Pro plan). |
| T3 | The schedule claims fixtures through the API before starting sessions (`piele.preview_dispatches`), one session per fixture. A claim holds for 45 minutes; a session that saved nothing is retried after that, at most 3 claims per fixture. |
| T4 | Staging is out of scope for now. |

## Completed changes

1. **Schema.** `supabase/migrations/20260925180000_preview_dispatches.sql`: `piele.preview_dispatches` (fixture id, attempt, dispatched at, teamsheet hash; primary key on fixture and attempt). RLS lets `piele_api` select and insert; update and delete are revoked. The Supabase GitHub integration applies it on merge to `master`.
2. **API.** `app/agent/previews.py`: the due rule is now "both teamsheets published, no preview, before kickoff, not claimed within the lease, fewer than 3 claims" (`first_preview` or `retry`). `claim()` inserts the next attempt; a concurrent claim of the same attempt loses on the primary key. `POST /v1/agent/dispatches` claims up to 8 due fixtures, soonest kickoff first. `GET /v1/agent/fixtures/due` stays as a read-only view; `latestRevision` is replaced by `attempt`.
3. **Agent.** `agent/schedules/prepare-previews.ts` (cron `*/15 * * * *`) calls `/dispatches` and hands each claim to `agent/channels/previews.ts`, which starts one session per fixture and attempt. The markdown schedule and the `get_due_fixtures` tool are removed; `instructions.md` now describes a one-fixture session. eve registers a channel only when it has a route, so the channel answers `GET /previews/health` with 204.
4. **Docs.** `apps/agent/README.md`, `apps/api/README.md`, `apps/api/CLAUDE.md`, `docs/production.md`.
5. **Vercel (production).**
   - `piele-api`: `PIELE_AGENT_TOKEN` added (sensitive, production). It takes effect on the API's next production deployment.
   - `piele-agent` created: root `apps/agent`, framework eve, Node 24.x, Git `VictorDercksen/piele`, `PIELE_API_URL=https://piele-api.vercel.app` and the same `PIELE_AGENT_TOKEN` (production). No deployment yet; `vercel.json` builds only `staging` and `master`.
