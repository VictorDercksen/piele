# Breadcrumbs for every shell page

Branch `claude/breadcrumb-navigation-pages-rwc5vp`, one commit on top of master's `92c023d`.
No pull request opened.

## Request

Breadcrumb navigation existed only on the match centre (a fixed "HOME" link from route
data). Make it a generic solution for every page reached from the main pages: Home, Duties,
Decisions and More.

## Completed

- `core/layout/shell/breadcrumbs.ts`: `Breadcrumbs`, a root service holding the trail of pages
  before the current one, derived from router events.
  - Main pages (no `parent` in their `PageData`: Home, Duties, Decisions, More) have no trail.
  - Any other page continues the trail of the page it was opened from: Home → Standings shows
    HOME, More → Standings shows MORE, Decisions → match centre (via a notification) shows
    DECISIONS, and deeper chains show every step.
  - Another fixture or round of the same page keeps the trail; opening a page already in the
    trail cuts it back to there.
  - A page opened directly (deep link, reload) or in another league shows its `parent`:
    Home for the match centre, More for Standings, Constitution and the captain's desk.
  - The desktop and mobile navigation bars pass `FROM_NAV_BAR` as navigation state, so their
    pages start afresh (desktop "Standings" shows no breadcrumb).
  - Back and forward restore each history entry's trail (by the restored navigation id,
    checked against the entry's path because ids restart after a reload).
  - Pages outside the shell (profile, welcome) leave the trail as it was.
- `page-data.ts`: `Crumb` type, required `label`, `parent` documented as the direct-entry
  fallback. `app.routes.ts`: labels on every shell page; `parent: More` on Standings,
  Constitution and the captain's desk.
- `shell.html`/`shell.ts`: the breadcrumb renders the trail (arrow on the first crumb, then
  `ROUND NN / EYEBROW` as the current page); nav links carry `[state]="navState"`.
- `CLAUDE.md`: one paragraph on `PageData` and `Breadcrumbs`.
