## How Jev is used

Before this session Jev was not called anywhere; it existed only in the plan (handoffs `2026-09-25_09-43-10_machine-agent-plan.md` and `2026-09-25_10-11-21_match-previews.md`). Jev is TypeSafe AI's model: `POST https://api.typesafe.ai/v1/systemone` with a bearer API key, `model` (`jev-latest` currently resolves to `jev-1.13.0`), a `state` and named typed questions; a Choice answer returns a probability per option. Docs: https://docs.typesafe.ai (index at `/llms.txt`). The documented weak spots (arithmetic, dates, large irrelevant state) shaped the request below. The endpoint is reachable from the cloud container; without a key it answers 403, with a wrong key 401.

## Completed changes

1. **API, shared with the backtest** (`apps/api/app/agent/`).
   - `state.py`: `build_state(fixture, source, now)` reads a `StateSource` (fixtures, teamsheets, weather, results). Production passes `LiveSource` (bundled schedule and match centre, results `None`, so form stays "unavailable"). Every source is wrapped in `BeforeKickoff`, which raises `LeakError` for fixtures, teamsheets or results from the fixture's kickoff onward and for any forecast but the fixture's own. New form section when results exist: last five results and the season record with table position (4/2/0, try bonus at 4 tries, losing bonus within 7; playoffs excluded from the table).
   - `jev.py`: the 13 result bands, the fixed `result_band` Choice question, `jev_state` (a compact view in words: stage, venue, forecast, each side's club, travel, rest, form, line-up, selection changes, regulars missing, average age; no dates, hashes or feed metadata), `build_request`, `request_hash`, `question_hash`, `ask` (retries 429, 529 and 5xx with backoff) and `distribution` (validates the 13 keys, tolerates rounding up to 0.02, renormalises).
   - `pick.py`: winner is the side with the highest total probability (ties home, away, draw); margin maximises the chance of landing within 5, with each band spread evenly over its margins (31+ over 31 to 45). This replaces the plan's "band midpoints" wording with an even spread.
   - `scoring.py`: `ScoringRules` version `superbru-super-rugby-2026-09-unconfirmed-for-urc` (win 1, margin 0.5 within 5, grand slam needs 4 or more matches). Bonus and grand slam points are not added.
   - `routers/agent.py` passes `LiveSource`. `catalogue.py` gains the nine past-season venues. `providers/weather.py` splits out `forecast_at` so the backtest parses forecasts the same way.
2. **Backtest** (`backtest/`): `common.py`, `collect.py`, `archive.py` (the downloads as a `StateSource`), `anonymise.py` (per-season seeded pseudonyms; the city is dropped; a check that no real club, player, venue or city name is left, which stops the replay if one is), `baselines.py`, `replay.py`, `score.py`, `results/decision-rule.md` (proposed rule, to confirm before the first Jev run), `tests/`. The README describes running and cost.
3. **Tests**: `apps/api/tests/test_machine.py` (guard, form, table, request, bands, validation, retries, pick against hand-worked distributions, scoring) and `backtest/tests/test_backtest.py` (synthetic season through the archive and guard, anonymisation, baselines, metrics). `apps/api/pyproject.toml` adds `../../backtest/tests` to `testpaths`, so CI's `uv run pytest` covers them.

## Data collected (git-ignored `backtest/data/`)

- Five seasons, 755 matches, all `result`, with try events. The nine venues missing from the catalogue matched the earlier handoff (61 matches).
- Line-ups for every match through the API's own teamsheet provider. One bio lookup failed with a protocol error, so one match has no birth dates; many older players have no birth date in the feed anyway.
- 109 venue-season files from the Open-Meteo Historical Forecast API. It returns no `precipitation_probability` for most places. The Previous Runs API was not used: it answered "daily limit exceeded" from the shared address during the check.
