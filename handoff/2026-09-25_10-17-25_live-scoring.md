# Live scoring

Request: plan live scoring for URC games, then implement phases 0 to 2 and run the phase 0 feed watcher during round 1. The user confirmed live URC match scores (not Superbru points) and asked for a scoring timeline on the match page.

## Findings (phase 0 so far)

- The URC GraphQL feed (`https://www.unitedrugby.com/graphql`) is reachable from the cloud container again. It returns HTTP 403 to httpx's default User-Agent; the API already sends `Piele/0.1 match centre`.
- `matchstats` carries `match_status`, `match_period`, `home_score`/`away_score`, `stats_data { period periodTypeId minute second timerRunning finalised matchWinner homeTeam/awayTeam { score { currentScore htScore ftScore finalScore } } events { ... } }`. Seasons 2021/22 to 2025/26 all read `result` / `post match` / 150 / `finalised: 1`. Pre-match fixtures read `fixture` / `pre match` / 10.
- Event types: period markers, try (try, penalty try), goal kick (conversion, penalty goal, drop goal and misses), card (yellow, red), sinbin end, substitution. `time` gives stoppage display such as `80+1`.
- The feed sends `cache-control: public, max-age=3600` but Cloudflare reports POST as `DYNAMIC`. Freshness during play is not yet verified.
- Not yet seen: in-play status and period strings, and how half time is represented. The parser handles a `half time` period and falls back to the last period event being `first half end`.

## Completed

API (`apps/api`):
- `app/matchcentre/providers/scores.py`: one round query by match ids; per-match state (`scheduled`, `live`, `half_time`, `full_time`, `postponed`, `cancelled`), minute, clock, scores, half-time scores; a timeline of scoring events and cards with the running score; snapshot lifetime 20 s while any match is within 15 min before to 3 h after kickoff and not finished, else until the next kickoff window (1 min to 6 h).
- `service.py`: `round_scores()` and a `score` section in the match centre, both from the `scores:round:<n>` snapshot. No feed call before a round's first kickoff window.
- `GET /v1/rounds/{round}/scores` in `routers/matches.py`; `score` added to the `MatchCentre` response; `Schedule.round()`.
- `tests/test_scores.py` (7 tests); `tests/test_matches.py` fake upstream answers the scores query.
- No Vercel CDN caching was added: the `no-store` middleware stays and the Postgres snapshot bounds feed calls. This departs from the plan's `s-maxage` item.

Web (`apps/web`):
- `core/api/live-scores.service.ts`: `LiveScoresService` requests the selected round's scores once a kickoff window opens, polls every 30 s while a match is in play and the tab is visible, refreshes on tab focus, and keeps the last scores through a failed refresh. `withScore` and `inPlayWindow` helpers.
- `core/api/match-centre.models.ts`: score contracts. `Fixture` gains `state` and `minute`; `score` is now filled.
- `RoundViewService.fixtures` merges live scores, so the ribbon, home hero and match page all follow.
- `core/competition/match-status.ts`: hero score bug and ribbon status (LIVE 54', HALF TIME, FULL TIME, POSTPONED).
- `currentRoundId` keeps a round current until two hours after its last kickoff, so a live final match of a round is the default view.
- Match page: scoring panel with a two-sided timeline, half-time divider, card markers, running scores and a "delayed" tag when a live score is over two minutes old (`features/match/scoring.ts`); the match centre reloads on each live poll.
- Specs: `live-scores.service.spec.ts`, `match-status.spec.ts`, `scoring.spec.ts`, extra `currentRoundId` case; e2e `e2e/live-scoring.spec.ts` (live, second half, full time, mobile overflow; no request before a round starts).

Other: `scripts/watch-urc-live.py` (phase 0 watcher); README, apps/api/README.md, apps/api/CLAUDE.md and fixtures/README.md updated.

## Phase 0 result (25 September, evening)

- The watcher ran from 18:20 UTC. Pre-match polls answered in 1.6 to 2.3 s. From 18:40:57 UTC, five minutes before kickoff, every request to `www.unitedrugby.com/graphql` timed out (41 in a row), including `{ __typename }`; one probe got HTTP 504.
- By 19:15 UTC Cloudflare returned "Sorry, you have been blocked" (403) to this container's egress IP, for the GraphQL endpoint and the home page alike. The watcher was stopped at about 19:20 UTC. No in-play values were captured, so the live status and period strings and the half-time representation remain unverified.
- Cause unknown: match-night load, a bot rule against datacenter IPs, or the watcher's 30-second polling. The production API would poll from Vercel's shared egress at up to one request per 20 s per round, so the same block can hit it.
- The official stats site (`stats.unitedrugby.com`) reads the same GraphQL endpoint; there is no separate live source behind it.
- ESPN's public scoreboard (`site.api.espn.com/apis/site/v2/sports/rugby/270557/scoreboard`) answered in 0.5 s with live states (`STATUS_FIRST_HALF`) and scores for all three matches; its clock read 1' and looked stale. It is unofficial and its terms were not reviewed.
- The pre-match capture was not committed; it matched the shapes already covered by the tests.
