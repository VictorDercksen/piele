# Referee's-card alert service

## Request

Create an alert service that shows an appropriately coloured snack for problems with inputs,
uploads and the like, rugby inspired, and stop showing those as inline notices. The user chose,
from options offered: the referee's-cards look; everything including field validation moves to
the snack; errors persist while the rest time out. Planned by the orchestrator and implemented
by five subagents (one foundation, four migration groups in parallel).

## Completed

### Foundation (`apps/web/src/app/core/feedback`)

- `alert.service.ts` replaces `toast.service.ts` (deleted). `AlertService.alerts` is a signal of
  at most three `Alert`s (oldest first); `show(severity, message, options)` and the shorthands
  `error`, `warn`, `success`, `info`; options `key` (replaces the card with the same key),
  `details` (short lines under the message), `action` (a button that runs, then dismisses),
  `timeout` (override; `null` stays). Defaults: error stays, warning 8 s, success and info 5 s.
  An equal card (same severity and message) replaces the one showing. `dismiss(id)`,
  `dismissKey(key)`, `clear()`, `pause(id)`/`resume(id)` keep the remaining time.
- `layout-insets.ts`: `LayoutInsets.bottom`, the fixed mobile navigation's height, set by the
  shell where it already measures `--nav-height`, reset on destroy.
- `alert-snack/`: `app-alert-snack`, loaded by `app.ts` with a dynamic import after the first
  render (mounting it statically put the initial bundle over the 740 kB budget; it is 735.9 kB
  now). The stack is a `popover="manual"` element in the top layer, centred at the foot of the
  viewport above the mobile nav. A native modal `<dialog>` makes a popover raised behind it
  inert (checked in this Chromium: it rendered but could not be clicked or focused), so while a
  modal is open the stack is moved inside the topmost modal and back out when it closes or
  leaves the page (a `MutationObserver`). Hidden, the popover is `display: none`, so it adds
  nothing to the page's scrollable area. Each card: eyebrow "Red card", "Yellow card", "Try" or
  "Referee"; `role="alert"`/`aria-live="assertive"` for errors, `status`/`polite` otherwise;
  the message, optional details, optional action, and a white stitched dismiss button. Colours
  `#c8321e`, `#e6b422`, `#237548` (darkened from the plan's green for AA contrast), `#164551`.
  Cards enter sliding up with a slight rotation (drawn from a pocket) and leave through
  `animate.leave`; under reduced motion only opacity fades. Hover or focus pauses a card's clock.
- Shell: the inline `.toast` and the league-load banner are gone (`shell.html`, `shell.scss`,
  the `.league .toast button` selectors in `styles/ui.scss`). The league-load failure is a
  persistent red card keyed `league-load` with a Retry action, dismissed when the error clears
  or the shell leaves. `selectRound` no longer clears messages.
- `shared/rules-fields/rules-form.ts`: `ruleProblems(group, lastRound)` lists a rules form's
  invalid fields (`{ field, message }`, `field` the id suffix under `idPrefix`) for the parents'
  cards; `rules-fields` keeps `aria-invalid` and no longer renders field errors.

### Migration

Every inline problem notice for inputs, uploads, saves, clipboard, storage and network is now a
card. Field problems are one yellow card per submit attempt, keyed per form (a resubmit replaces
it, a valid attempt dismisses it), the first problem as the message and up to two more in
`details` then "and N more."; the failing controls are `aria-invalid` and focus moves to the
first. Operation failures are red cards. The old toast successes are green cards; "unchanged"
notes are teal.

- Sign-in (email, password → warn; auth failures → error; the confirm-email notice stays),
  join (claim or names reload failure → error), no-league and league-switcher join code → warn,
  profile editor (name, team, and the five photo checks → warn; save, upload and the
  local-storage failure → error).
- Captain's desk: rules card (`ruleProblems` → warn; save → error), team sheet (add-member and
  email checks → warn focusing the row's input; add, email save, reinstate, playback → error),
  appearance card (emblem checks → warn; save/upload → error), join link card (clipboard refused
  with the link in the message, open joining → error), picks card (grid margins → warn keyed
  `picks-grid` with rows still flagged; `picks_locked` → warn, other refusals → error; override
  range → warn; override save → error). `features/captain/alert-details.ts` builds detail lines.
- Manage: the page's success line → success; league card rename (name, zone, rules) and captain
  choice → warn; clipboard, Add me and rename failures → error; create-league form: all client
  checks → one warn keyed `create-league` ("Member N: …" rows; a repeated Superbru name warns
  once when it first appears); `slug_taken`/`invalid_slug` focus the slug, `duplicate_member`
  the first member's Superbru name, `unknown_captain` the captain select; unmapped failure →
  error. `features/manage/form-problems.ts` builds detail lines.
- Duties, decisions, match: evidence dialog (file and completed-at checks → warn; submit/upload
  → error), create-duty dialog (member, deadline → warn; create → error), reason dialog (reason
  required → warn keyed `reason`, dismissed on close or a valid submit; action failure → error),
  duty card playback → error, vote dialog → error, picks panel (side, margin → warn keyed
  `pick-{fixtureId}`; `picks_locked` → warn; other → error).
- Kept as inline empty states with Try again (not notifications): the match centre's failed
  state and section "unavailable" lines, the preview, the join page's "That link does not work."
  and "Not just now.", the no-league account error, the manage list, captain-candidates and
  competitions load errors, the notifications flag's stale line. `.error-message` in `ui.scss`
  and `.field-error` in `manage-fields.scss` remain for those.
- `CLAUDE.md`: an "Alerts" paragraph under UI conventions; the management-centre sentences on
  refusals and row errors updated.
