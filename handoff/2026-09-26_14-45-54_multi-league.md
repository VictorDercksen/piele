# Multi-league: The Pavilion, league switching, emblems, joining, removal, management centre

Branch `claude/multi-league-architecture`, nine commits on top of master's `f9ae730`. No
pull request opened.

## Request

Architect and then implement one account in several leagues, with future competition
types in mind: name the product (working name The Pavilion; Piele stays the first league),
league emblems, a league switcher top left, join links, removing members, and an admin-only
management centre. Decisions recorded in `docs/multi-league-architecture.md` (URL-scoped
leagues, favourite team per membership, presets and uploads for emblems, join-code links,
rugby only for now, one global admin with captain rights everywhere alongside per-league
captains). Implementation was orchestrated with subagents, one contract per phase, API and
web in parallel.

## Operator steps before release (see `docs/production.md`)

1. Set the admin flag once on production:
   `update piele.users set is_admin = true where email = '<your sign-in email>';`
2. Push migrations with the code. In the window between the migrations applying and the
   new API deploying, the old API cannot record milestones or claim names, and its profile
   and notification saves fail; favourite-team changes made then are lost.
3. Share the new join link from the captain's desk (the old `/claim` page is gone). The
   existing Piele league got slug `piele` and a random join code from the migration.
4. The infrastructure renames (repo, Vercel projects, Supabase projects) are optional and
   change the `*.vercel.app` origins; do them with custom domains.
