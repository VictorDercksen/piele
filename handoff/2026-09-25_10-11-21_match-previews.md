## Jev backtest (planned)

Added on request: the folder `backtest/` with a README and a git-ignored `data/`. No backtest code exists yet. This is how it would be built (plan Phase F).

### What was checked on 25 September 2026

- The public URC feed (`matchstats(season_id: [...])`) serves five past seasons, 202101 to 202501, 151 matches each, 755 in total. Every match has `home_score`, `away_score`, `match_datetime`, `venue` and 23-player line-ups through `matchstats(match_id: [...])`.
- All team ids in those seasons are in `app/matchcentre/catalogue.py`. Nine venues are not, covering 61 matches: Swansea.com Stadium (30), Electric Brewery Field (12), Danie Craven Stadium (6), Principality Stadium (4), Croke Park (4), Cardiff City Stadium (2), Hastings Insurance MacHale Park (1), Nelson Mandela Bay Stadium (1) and Twickenham Stoop (1). They need coordinates and a country for weather and travel.
- Jev (TypeSafe AI, early access since 15 September 2026): `POST https://api.typesafe.ai/v1/systemone` with a model alias (`jev-latest`), the state as text or JSON, and named questions of type choice (up to 255 options), score (2 to 10 levels) or noul (yes/no). Each answer has a decision, a probability per option and a confidence. $0.042 per million input tokens, output free. No published knowledge cutoff. Not yet tried with an account.

### Prerequisites from other phases

1. **Phase D in the API, in Python:** `app/agent/jev.py` builds the Jev request (the 13-band `result_band` question and the serialised state), and `app/agent/pick.py` turns a distribution into a winner and margin. The production agent should forward the API-built request rather than compose its own, so production and backtest send identical payloads.
2. **Phase E scoring:** a versioned Superbru scoring configuration (`scoring_version`) with win, margin and grand slam points. The backtest imports it rather than re-implementing it.
3. **A refactor of `app/agent/state.py`:** `build_state` takes a data source (schedule, teamsheets, forecast, results before a given time) instead of calling `MatchCentreService` directly. Production passes the cache-backed providers; the backtest passes downloaded files. The data source refuses anything at or after the match's kickoff, and a test proves it. With results available, the state gains its form section in both uses.

### Steps

1. **`collect.py`, run once.** For each season: the fixture list with scores, rounds, team ids, kickoff and venue; each match's line-ups and player birth dates through the existing `teamsheets.fetch_teamsheets` and `fetch_bios`; and the kickoff-hour forecast from Open-Meteo. Use the Previous Runs API (values from the run one or two days before kickoff) if it serves these dates. Otherwise use the Historical Forecast API and note that its short-lead forecasts are more accurate than a real two-day-ahead forecast. Raw responses go to `data/` with the query and retrieval time; existing files are skipped; about one request a second (roughly half an hour for all line-ups).
2. **`replay.py`.** Walk each season in kickoff order. For each match, build the pre-kickoff state, send the production Jev request and record the distribution, the model version Jev reports and the request hash. Cache Jev answers by request hash in `data/`, so reruns are free and reproducible. Run two arms: named, and anonymised (stable per-season pseudonyms for clubs, players and venues, keeping country and travel). The difference between them estimates how much Jev recalls rather than predicts.
3. **`baselines.py`.** Home side by 7; the higher-placed side at that point of the season by 7; and an Elo rating with home advantage, whose margin distribution is a normal fitted to the Elo difference. Tune the Elo only on 2021/22. Every baseline outputs the same 13-band distribution, so all models are scored the same way.
4. **`score.py`.** Picks come from `app.agent.pick` for every model. Report Superbru points (win and margin; grand slam per round; bonus points excluded) per round and per season, plus log loss and Brier on home, draw or away, ranked probability score on the bands, and a calibration table. Give confidence intervals by resampling rounds, because a season is only about 150 matches. Write `results/<date>/`: `summary.md`, per-match rows as CSV, and `settings.json` (Jev alias and version, question hash, code commit).

### Protocol

- 2021/22 tunes the baselines only; results are reported for 2022/23 to 2025/26. Jev is not tuned.
- Before the first run, write down the decision rule in `results/`. Proposed: the Machine uses Jev if, on the anonymised arm, it beats the Elo baseline on Superbru points and on ranked probability score. Probabilities stay hidden before kickoff until then (plan decision O1).
- Leakage stays in every report: the final match-day line-ups may include changes made after the 48-hour announcement, and Jev may have seen these seasons in training. The clean test is 2026/27. From Phase D on, every Jev distribution is stored before kickoff (`piele.machine_picks`), and `score.py` should score those the same way as the season goes on.

### Running and cost

- Local or a manual CI job, never on Vercel. Proposed command: `uv --directory apps/api run python ../../backtest/replay.py`, with the scripts putting `apps/api` on the import path. The Jev key lives in a git-ignored `.env`.
- Estimate (unmeasured): 755 matches × 2 arms = 1,510 Jev calls. At about 5,000 input tokens each, that is 7.5 million tokens, about $0.32.
- Tests for the kickoff guard, baselines and scoring go in `backtest/tests/` and run with the API's pytest.
