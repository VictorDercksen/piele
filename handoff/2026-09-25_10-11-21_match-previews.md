## Completed changes

1. **Schema.** `supabase/migrations/20260925120000_match_previews.sql` adds `piele.match_previews`: append-only revisions per fixture (`unique (fixture_id, revision)`), hashes of the inputs and teamsheets, summary, key factors, sentiment, sources, models, usage and run id, with a partial unique index on `(fixture_id, run_id)`. RLS policies let `piele_api` select and insert only; update and delete are revoked. The Jev distribution column is left for Phase D.
2. **API** (`apps/api/app/agent/`, `app/routers/agent.py`).
   - `auth.py`: `PIELE_AGENT_TOKEN` bearer check, constant-time, separate from member auth. Unset means the routes answer 503. Production refuses a token shorter than 32 characters.
   - `state.py`: `GET /v1/agent/fixtures/{id}/state` returns both teamsheets, changes from each side's previous teamsheet (starters in and out, shirt changes), regular starters missing (started 2 of the last 3), average ages (starters, forwards, backs, replacements), bench forward/back split from position names, rest days, travel (`home`, `domestic`, `cross_border`, `intercontinental`, using new club and stadium countries in `catalogue.py`), the kickoff forecast, `teamsheetHash` and `stateHash`. Earlier teamsheets come through the existing snapshot cache. Form is reported as unavailable until results are recorded (Phase A).
   - `previews.py`: `GET /v1/agent/fixtures/due` lists fixtures inside the 3-day teamsheet window that have published teamsheets and either no preview, a changed teamsheet hash, or kickoff within 2 hours and a preview older than 6 hours. Never after kickoff.
   - `POST /v1/agent/previews`: strict validation (`models.py`): unknown fields rejected, text trimmed and free of control characters, length limits, http(s) source URLs only, 1 to 20 sources, every key factor and mood citing existing source indexes, sentiment -2 to +2, hex hashes. Refused after kickoff. Stored as the next revision; a repeated `runId` returns the stored preview with 200.
   - `GET /v1/matches/{fixtureId}/preview` for active members: the latest preview or `preview: null`. Models, usage, run id and hashes are not returned.
   - `MatchCentreService.teamsheets()` and `.weather()` are now public so the state builder reuses them.
3. **Web.** `features/match/match-preview/` adds the "Piele preview." panel under the teamsheets and forecast: summary, mood and key factors per side with numbered citations, the source list (external links, `noopener noreferrer nofollow`), and an "as of" note. Loading, error with retry, and "no preview yet" states. It loads only when the build has the API and Supabase sign-in (`MatchCentreService.previewConfigured`). All agent text is bound as text.
4. **Agent** (`apps/agent`, eve 0.66.3, new). Root agent (`anthropic/claude-opus-5.5`, no default tools, no self-delegation, per-session token and cost caps) with `get_due_fixtures`, `get_fixture_state` and `save_preview`. The state tool keeps each fixture's hashes in eve session state, so `save_preview` sends them without the model copying them; it also lists the URC and Open-Meteo as citable sources for state facts. `team-researcher` subagent (`anthropic/claude-sonnet-5`) has only `web_search` and an allowlisted `web_fetch`, and returns a structured result. `save_preview` rejects sources outside the allowlist. Schedule `10 */2 * * *` UTC. Session routes accept only this project's Vercel OIDC tokens and local dev. `vercel.json` limits builds to `staging` and `master`.
5. **Other.** CI job `agent` (npm ci, typecheck, test, build). Smoke check that `/v1/agent/fixtures/due` answers 401 or 503 without the token. Root scripts `setup:agent` and `test:agent`. README, `apps/api/README.md`, `apps/agent/README.md`, `docs/production.md` and both `CLAUDE.md` files updated.
