# Pavilion match chat: fixture-scoped questions on the match page

Recorded on 2026-10-01 in Africa/Johannesburg time. Paths are relative to the repository root. Branch `claude/ecstatic-hypatia-1c7m9t`.

## Request

Plan and build a chat where a league member asks the Pavilion about one fixture (teamsheets, forecast, preview, their own pick, the pool's picks once visible), reusing the preview agent's research, with the backend holding the auth and abuse controls. Orchestrated with three subagents (agent project, API, web) from one shared contract; the chat model's prompt was drafted by the orchestrator from Anthropic's prompting guidance (role, purpose and audience, XML-tagged sections, numbered steps, five diverse examples, "do this" phrasing).

## Design

- The browser talks only to the API. The API verifies the member, enforces the limits in the database, builds a context document from data the member may already read, calls the agent project's `POST /chat/turn` with `PIELE_AGENT_TOKEN`, relays the AI SDK UI message stream unchanged to the browser and stores the transcript.
- The agent turn is stateless: one `streamText` call through AI Gateway, no tools, no eve session. The model sees only the system prompt, the context document and the last ten messages. There is nothing it can reach that the API did not send.
- Scope is one fixture. The request shape and the tables reserve `scope.kind = 'round'` for a later round scope.
- Decisions taken by default, open to change: the chat opens three days before kickoff and closes two days after; no per-league captain toggle (one operator flag); limits 6 questions per match, 20 per member per league per rolling day, 400 per deployment per rolling day, 500-character questions, 500 output tokens.

- `app/routers/chat.py`: `GET`, `POST`, `DELETE /v1/leagues/{leagueId}/matches/{fixtureId}/chat`. ## Unresolved / next steps

- Not run against a real model, the live API or Supabase. First real turns to check: Gateway auth from the custom channel route on Vercel (OIDC outside an eve session), whether DeepSeek's hidden reasoning eats into the 500-token output cap, and the token and cost figures in Agent Runs.
- Vercel's Python runtime streaming `StreamingResponse` incrementally and running the shielded `finally` after a client disconnect is untested there. `apps/api/vercel.json` sets no `maxDuration`; a turn is provider reads plus up to 60 s of relay.
- A member asking about two fixtures at the same moment can exceed the daily count by one (the advisory lock is per thread). A client disconnect does not stop the agent's model call (the 45 s timeout does).
- Round scope, research tools on the chat turn, pre-answered questions per fixture and eve evals remain as planned.
- To enable in an environment: deploy the agent project, set `PIELE_AGENT_URL` and `PIELE_CHAT_ENABLED=true` on the API, apply the migration through the Supabase integration.
