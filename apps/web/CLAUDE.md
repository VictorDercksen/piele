# CLAUDE.md

Adapted from CtrlFleet/src/fc-app-web/CLAUDE.md for The Pavilion frontend. This file is the frontend coding guide for all agents.

## Session handoffs

Before starting work, read the latest Markdown handoff in [../../../handoff/](../../../handoff/), selected by the timestamp in its filename. Before ending each session, write a new handoff there named `YYYY-MM-DD_HH-mm-ss_<feature>.md`, using Africa/Johannesburg local time and a short kebab-case feature name. Record the request, completed changes, relevant files, checks actually run and their results, unresolved issues and next steps. Distinguish completed work from proposed work. Preserve previous handoffs and never include secrets.

## Project and authority

The Pavilion is a private rugby league application (called Piele until September 2026). Piele is now the name of its first league: use "The Pavilion" where text means the app and "Piele" only where it means that league. Environment variables (`PIELE_*`), the `piele` schema and the `piele-crest.png` asset keep their names. Read ../../../piele-application-plan.md and ../../../piele-application-design.md from the repository root context (the source documents are one level above the piele monorepo). User decisions take precedence over proposed plan defaults. Floodlights is the selected design. Preserve the round-scoped season timeline on desktop and mobile.

Members sign in with Supabase Auth (Google or email and password) through `core/auth`: `AuthService` owns the session, `authInterceptor` attaches the access token to The Pavilion API calls only, and the `signedIn` and `signedOut` guards order navigation. Builds without a Supabase project (the sample-data development build) skip sign-in.

An account can belong to several leagues, and every league page sits under the league's slug. Routes (`app.routes.ts`): bare `/sign-in`, `/join/:code` (a league's join link: its name, emblem or monogram and unclaimed Superbru names, then the two-tap claim through `POST /v1/join/{code}`, which reloads the account and opens `/{slug}`; an account already in the league sees "You're in" and a link to it), `/manage` (the management centre, below) and `/no-league` (a signed-in account without leagues: a join-link-or-code field, `joinCodeFrom` accepts a pasted link or a bare code, and sign-out; it also shows an account that failed to load, with a retry). `/:league` holds `welcome` and `profile` (full-page, outside the shell, because the favourite team is per league) and the Shell with `''`, `match/:fixtureId`, `standings`, `duties`, `decisions`, `constitution`, `captain` and `more`. Guards run `signedIn`, then `leagueRequired` (`core/league/league.guards.ts`: loads the account, resolves the slug, and sends an unlisted or API-refused league to `/`), then `profileRequired`/`profileMissing` and `captainOnly`. `/` (`leagueHome`) opens the account's last used league while it is still listed, else its first membership, else (the admin with no memberships) the first listed league, else `/no-league`, keeping the query string. The pre-slug paths (`/standings`, `/duties`, `/decisions`, `/constitution`, `/captain`, `/more`, `/profile`, `/welcome`, `/match/:id`) redirect to the same path under that league (`legacyLeaguePath`), so those words and `sign-in`, `join`, `no-league`, `manage`, `api` and `v1` cannot be league slugs (`core/league/league-slugs.ts`: `SLUG_PATTERN`, `RESERVED_SLUGS`, `deriveSlug`, `slugProblem`, the same pattern and list the API checks). Route titles read "Standings · The Pavilion". Guards only choose where navigation goes; the API decides what an account may see. In-app links go through the current league: templates use the impure `leaguePath` pipe (`[routerLink]="'/duties' | leaguePath"`), code uses `LeagueContext.url('/duties')`, and `LeagueContext.within(url)` gives the path after the slug. Keep league-relative paths (`/duties`) in data such as notices and feed items.

`LeagueContext` (`core/league/league-context.ts`) holds the account document (`account`, from `GET /v1/me` once per session, again after a claim via `reloadAccount()`), `leagues` (`LeagueSummary`, the account document's league entry in `league.models.ts`), `current`, `slug`, `name`, `isAdmin`, `isMemberOfCurrent` and `competition` (from the registry). `select(slug)` sets `current`, `CompetitionService.current` and `LeagueTime.zone` (the league's `timezone`), calls `LeagueData.selectLeague`, waits for the API client's league load and records the last used league (`PUT /v1/leagues/{id}/me/last`, only when it changed). A league-scoped 403 `not_a_member` or 404 `unknown_league` marks the league refused for the session and returns to `/`, whether at load (the guard) or later (`HttpLeagueData.refused`). `signOut()` signs out, clears the context and the API client and opens `/sign-in`. The eyebrows ("PIELE / CAPTAIN'S DESK") and the footer ("THE PAVILION / PIELE / ROUND 02") show `current.name`, uppercase where the design is; the product wordmark lives on the sign-in page, the footer and the More page, not top left.

The shell's top-left block (`rail-brand` on the desktop rail, `club-brand` in the top bar) is the league switcher, `core/layout/league-switcher`: a button (`aria-haspopup="dialog"`, `aria-expanded`, named "{League}. Switch league") showing the crest, name and competition short name and season, which opens a dialog built like the notifications flag (local `open` signal, Escape and outside-pointer close, focus back on the button, focus moves to the current league's row on open). It is a popover on wide screens and, below 800 px, a sheet that drops from under the top bar with a scrim (the sticky top bar is its containing block, so it needs no fixed positioning inside the shell's container). It lists `LeagueContext.leagues`: one link per league with its crest, name and season, a "Current" tag and `aria-current` on the current league, "Captain" where `isCaptain`, "Not in this season" where `inSeason` is false; for the admin the rows are grouped "Your leagues" (with a membership) and "All leagues" (without one, tagged "Admin view"). Each row links to the same page under that league's slug (`LeagueContext.within(url)` then `url(path, slug)`), keeping `round` only between leagues on the same competition (a match page of another competition opens the home). Its "Join a league" field is a plain form (no forms module in the shell's bundle) that reads `joinCodeFrom` and opens `/join/{code}`. With one league the button still opens it. For the admin its last item is "Manage leagues", a link to `/manage`.

The management centre (`features/manage`, `/manage`, titled "Manage leagues · The Pavilion") is a lazy full page outside the shell in the profile page's style (the product wordmark, "Back to the clubhouse" to `/`), guarded by `signedIn` and `adminOnly` (`core/league/league.guards.ts`: loads the account and sends anyone but `LeagueContext.isAdmin` to `/`; the API answers 403 `admin_only` regardless). Its data is `AdminService` (`core/league/admin.service.ts`, models in `admin.models.ts`), an abstract root service whose factory picks `HttpAdminService` or, in the sample build, `SampleAdminService`: `leagues` (active first, then by name), `load()` (`GET /v1/admin/leagues`), `create(body)` (`POST /v1/admin/leagues`), `update(id, patch)` (`PATCH /v1/admin/leagues/{id}` with `name`, `timezone`, `status`), `appointCaptain(id, memberId)` (`POST .../{id}/captain` with `{ membershipId }`), `addMe(id, name?)` (`POST .../{id}/members/me` with `{}` or `{ displayName }`, then the list again), `competitions()` (`GET /v1/competitions`, once) and `captainCandidates(id)` (the claimed active members from `GET /v1/leagues/{id}/members`). Every change calls `LeagueContext.refreshAccount()` (which re-reads `GET /v1/me`, or the sample account), so the switcher follows before the promise resolves. The page lists each league as a card (`league-card`): crest, name, slug, competition and season, captain (or "No captain claimed yet"), counts, status tag, join code with "Copy link"; "Open" (a link to `/{slug}`), "Add me" (hidden when `myMemberId` is set), "Rename" (an inline form for name and time zone, focus in and back out), "Archive"/"Restore" (confirmed through the reason dialog's `noReason` mode with an `eyebrow` of its own; focus follows the league to the collapsed "Archived" `<details>` group or back to its heading) and a collapsed "Appoint a captain" panel (a select of claimed members, confirmed). The new-league form (`create-league-form`, a typed reactive form) derives the slug from the name until the slug is typed in, fills the time zone and season name (`{shortName} {season}`) from the chosen competition until edited, parses the members textarea ("Full name, Superbru name" per line, split at the last comma; `members-parser.ts`) into a preview with an error per line, offers the parsed names as captain, sends `captainEmail: null` while "The captain is me" is ticked (otherwise an email and "Also add me as a member"), reuses the preset tiles (`shared/emblem-picker`, also used by the appearance card) and an accent colour, and opens `/{slug}` on success. API refusals show by code: `slug_taken`/`invalid_slug` beside the slug, `duplicate_member`/`unknown_captain` beside the members, anything else at the top; focus moves to the field. The sample build's `SampleLeagueData` keeps its leagues in a signal (`sampleLeagues()`, `addLeague(seed)`), builds the sample account from them (`account()`: active leagues by name; the admin also sees leagues it is not in), and each `SampleLeague` has name, time zone, status, captain and membership signals (`update`, `appoint`, `addAdmin`), so creating adds a league to the switcher, archiving hides it (and its join code), appointing moves `captainMemberId`, and "Add me" makes the sample account a member outside the season. `?sampleAdmin=0` on the first page makes the sample account a plain member of Piele and the Pofadder Bowl (no Sample Third XV, no "Manage leagues", `/manage` goes to `/`).

League emblems (`core/league/emblems.ts`): an uploaded image (`emblemUrl`, a signed Storage URL), a preset crest (`emblemPreset`, one of `oak`, `anvil`, `lantern`, `compass`, `chevron`, `crown`, `wave`, `star`, drawn as `public/assets/images/emblems/{key}.svg` whose `#emblem` group uses `currentColor`), the Piele crest for slug `piele`, else the member monogram of the initials. `shared/league-crest` renders them in that order and tints the preset and the monogram's ring and face with `accentColour` (`--crest-accent`, the `--monogram-*` properties of `shared/member-avatar`; `#d9b36c` brass without one); presets are inline `<svg><use href="...svg#emblem">` so they inherit the colour. Signed URLs cannot go in `<img>` under the CSP, so `EmblemImages` (`core/league/emblem-images.ts`) downloads them once, checks the bytes are JPEG, PNG or WebP and shows a data URL. Pass `emblemPreset` and `accentColour` wherever a crest is drawn (shell, switcher rows, join page, profile poster).

Everything competition-specific sits behind the registry in `core/competition/registry.ts`: `COMPETITIONS` maps a competition id (`urc-2026-27`) to a `Competition` (`competition.models.ts`, built by `defineCompetition` in `define-competition.ts`) that carries the schedule snapshot, rounds and playoff labels, regular-round count, clubs (`team(id)`, `jersey(id)`, avatar and stadium artwork paths), club banners, venues, country flags, the ball and emblem, `currentRoundId`, `firstKickoff`, `buildRounds` and `locate`. The URC 2026/27 is defined in `urc-2026-27.ts` from the local official snapshot (`urc-fixtures.ts`, generated by `scripts/import-urc.mjs`) and the `teams.ts`, `club-banners.ts`, `stadiums.ts` and `countries.ts` catalogues; a new competition is one more definition and registry entry. `CompetitionService` is a facade over its `current` signal (the URC until the league context sets another); its getters (`rounds`, `currentRoundId`, `season`, `shortName`, `regularRounds`, `fixtureCount`, `playoffSlots`, ...) read that signal, so code outside `core/competition` never imports the catalogues directly and never hard-codes URC wording, round counts or playoff codes. League records (members, Superbru round standings, duties, marks, polls, the feed) come from the `LeagueData` provider for the current league: `HttpLeagueData` against the Python API when the build has an API URL and Supabase project, `SampleLeagueData` in development builds, clearly labelled as sample records, else `EmptyLeagueData` (with one local league, `piele`). `HttpLeagueData` is per league: `load(leagueId)` clears the previous league's records and loads `me` and the five record calls from `${apiUrl}/v1/leagues/${leagueId}`; `ensureLoaded` resolves its `membership` state (`member` also covers the admin viewing a league it is not in, where `isMember()` is false); `clear()` runs on sign-out and on switching. The sample build has three sample leagues in `core/league/sample-leagues.ts`, all on `urc-2026-27`: `piele` ("Piele", the sample member captains it; the original sample records; no emblem, so the Piele crest), `pofadder-bowl` ("Pofadder Bowl", Doempie captains it, the sample member plays, with its own standings, duties, feed and an unclaimed name; the `anvil` preset on `#c8742a`) and `sample-third` ("Sample Third XV", Hennie captains it, the sample account holds no membership: the admin view, with the ribbon and a monogram on `#3f8f6b`). The sample account is the admin (unless the first page carried `?sampleAdmin=0`), so it stewards all three (the captain's desk opens in each). `SampleLeagueData.selectLeague` switches every signal to that league's in-memory records, which keep their changes until reload, including removals, reinstatements, join codes and appearance; `currentMemberId` is null in `sample-third`, where attributed actions refuse like the API. `SampleLeagueData.preview(code)` answers `/join/:code` from the leagues' current join codes (rotated or closed codes stop working). The captain's desk (`features/captain`) is for the league's steward: `LeagueData.administers` (the league-scoped `me`'s `administers`, captain or admin) drives the `captainOnly` guard and every captain-only control (`RoundViewService.administers`); `isCaptain` means only the captain. When the league-scoped `me` has no `memberId` (the admin in a league it is not in) the shell shows the ribbon "Admin view. You are not a member of this league." and attributed actions (duties, evidence, decisions, votes) show the API's 409 `admin_not_a_member` message. The desk has, besides evidence review and the team sheet: a "Remove" text button on every team-sheet row except the captain's and the steward's own, opening the reason dialog with a required reason (`POST /members/{id}/withdraw`); its copy says "This name has no records yet and will be deleted." only for an unclaimed name with no duties or standings loaded, and the API decides. Withdrawn members (`LeagueData.withdrawnMembers`, from `GET /members?include=withdrawn`, which `HttpLeagueData` requests only for the steward and splits by `status`/`leftAt`) sit in a collapsed "Withdrawn" `<details>` group at the foot of the team sheet with the date, reason and "Reinstate" (`POST /members/{id}/reinstate`); rows disable while a request runs and focus moves to that group after a removal. The join link card (`join-link-card`) shows `{origin}/join/{joinCode}` (`LeagueData.joinCode`, only for the steward) with "Copy link" (Clipboard API, a visible "Copied" line, a hint when the browser refuses), "Rotate link" (`POST /join-code/rotate`) and "Close joining" (`DELETE /join-code`), both confirmed through the reason dialog's `noReason` mode; a closed league shows "Joining is closed." and "Open joining", which rotates. The appearance card (`appearance-card`) picks a preset (radio tiles), uploads an image (`prepareEmblem` in `core/profile/profile-photo.ts`: the photo pipeline cropped to a 512 px square JPEG, uploaded straight to private Storage through `POST /emblem/uploads`), removes the emblem and sets the accent colour (`<input type="color">`), then saves through `LeagueContext.saveAppearance` → `LeagueData.saveAppearance` → `PUT /appearance`, sending only the emblem field that changes (`emblemPreset`, or `emblemPath` for an upload; removal clears whichever kind the league has; never both) plus `accentColour` when it changed. The shell's crest follows the returned `me` at once and API builds then re-read `GET /v1/me`. The reason dialog remembers what had focus and gives it back when it closes. New feed kinds: `member_left`, `member_returned` (also "{name} is back as admin."), `emblem_updated`, `captain_appointed` ("{name} is captain.") and `league_restored` ("{name} is open again."); `member_joined` also reads "{name} joined the clubhouse as admin.".

The member's display name is the league's Superbru nickname; `ProfileStore.whenKnown` resolves false for the sample admin view, so no onboarding is asked for there. `ProfileStore` keeps the favourite team per league (the league-scoped `me`) and the photo per account, saves through `HttpLeagueData` (`PUT /v1/leagues/{id}/me/profile`, photos uploaded straight to private Storage), and in builds without the API keeps them in this browser: the name and photo under `pavilion-profile-v2`, the team under `pavilion-team-v1:{slug}` (a profile kept before slugs is read as Piele's). Sample and empty builds keep the notifications read state under `pavilion-notifications-read-v2:{slug}` too. Times are UTC instants displayed in the league's IANA zone by `LeagueTime` (`core/competition/league-time.ts`): its `zone` signal defaults to `Africa/Johannesburg`, formatting uses `Intl.DateTimeFormat` with that zone, `fromLocalInput` converts `datetime-local` values through the zone's offset at that instant (daylight saving included), and the visible abbreviation comes from the zone (SAST for Johannesburg, Intl's short name elsewhere). Components inject `LeagueTime` (templates use the `leagueTime` pipe with `zone()` in place of `DatePipe` offsets); the pure functions in the same file take the zone as their last argument. Never write "SAST" or a fixed offset in new code. The API is the authoritative house-mark calculator; `core/league/marks.ts` exists only for the sample league. The match page's Pavilion preview (`features/match/match-preview`) loads `GET /v1/competitions/{competitionId}/matches/{fixtureId}/preview` through `MatchCentreService` only in builds with the API and Supabase sign-in; agent-written text is bound as plain text, never `innerHTML`. The notifications flag in the shell (`core/layout/notifications-flag`) shows `core/league/notifications.service.ts`'s stream for the current round: the league feed plus the competition events from `GET /v1/competitions/{competitionId}/rounds/{round}/updates` (`core/api/round-updates.service.ts`), with the member's read state (a high-water mark plus keys read individually, saved through `LeagueData.saveNotificationsRead`, server-side in API builds) and a 10-minute refresh that drops to 2 minutes while a match is in play.

## Actual stack

Angular 22 standalone components, signals, zoneless change detection, TypeScript, RxJS and component SCSS. The CLI uses @angular/build:application. Local fonts, crest, jerseys and team artwork live in public/assets. Spartan is the selected component library. Its CLI and MCP are installed as local development dependencies, with the MCP configured in the workspace's .codex/config.toml. The generated Slate theme lives in src/styles.scss, with dark mode enabled on the root HTML element and Titillium Web as the theme font. Tailwind 4 is compiled through .postcssrc.json. Spartan Brain and Angular CDK are installed for the theme preset. No Helm components have been generated yet. Firebase, Angular Material and CtrlFleet services are not installed. Do not introduce them solely to match the source guide.

Use the Icon component in `shared/icon` and accessible native controls until the relevant controls are migrated to Spartan. Text links and buttons carry a trailing Lucide icon from `@ng-icons/lucide` (`<ng-icon class="link-icon">`, registered per component with `provideIcons` in `viewProviders`): `lucideExternalLink` for external sites, `lucideArrowRight` for in-app navigation. Do not use emoji or Unicode arrow and check glyphs in the interface. Shared Floodlights primitives (tags, buttons, tabs, empty states, dialogs) live in `src/styles/ui.scss`. Everything else is component-scoped SCSS. Use native dialog focus handling in the prototype. Angular CDK is available for later overlays. Keep branding in shared CSS custom properties. Bind data-driven team colours through style properties, never unsanitized HTML or CSS strings.

## Component and state rules

1. Use standalone components and ChangeDetectionStrategy.OnPush.
2. Use input(), output(), viewChild() and viewChildren(). Do not add decorator-based input/output or query APIs.
3. Use signal() for mutable display state, computed() for derived state and readonly fields for immutable configuration. Prefer readonly arrays for static catalogues.
4. Inject dependencies using inject() fields. Constructors are for initialization only.
5. Use native @if, @for and @switch. Track collections by stable IDs.
6. Use typed reactive forms for new profile and onboarding forms. Do not use two-way ngModel bindings with signals. Read changing form state reactively when used in template conditions.
7. Avoid any. Narrow DOM events with typed handlers. Do not scatter $any casts through new templates.
8. Keep asynchronous I/O and persistence in services. Do not call services directly from templates. Prefer computed state over effects. Use afterRenderEffect only for DOM work.
9. For RxJS, use observer objects in subscribe and takeUntilDestroyed for teardown. Do not maintain Subscription lists.
10. Use host metadata instead of HostListener/HostBinding. Keep imports and providers at the bottom of component metadata with one item per line when there is more than one.
11. Put component-local interfaces after the class or in dedicated model files. Layout: `src/app/core` for app-wide services, data sources, guards and the shell (`core/layout`), `src/app/features/<page>` for routed pages and their dialogs, `src/app/shared` for reusable presentational components. Each page is a lazy route in `app.routes.ts`, titled through route `data`. The selected round lives in the `round` query parameter via `SelectedRoundService`, and pages read round-scoped league data from `RoundViewService`.
12. Use SCSS classes for layout. Inline style bindings are for genuinely data-driven values such as favourite-team colours.
13. Build responsive layouts that share behaviour. Separate mobile components only when interaction differs materially. Do not duplicate business state for desktop and mobile.
14. Never put secrets or privileged Supabase keys in frontend files. Route guards do not provide authorization. Production mutations go through the planned Python API.
15. Validate browser-stored preferences before using them. Handle unavailable storage, invalid files and image decoding errors with visible feedback. Never claim browser-local profile changes were saved to a server.

## UI conventions

Use Floodlights' dark rugby presentation, original action artwork, jerseys for matchups and restrained accents. Personal cards, avatars and the current member's rows use their favourite team's colour and artwork. Preserve readable contrast regardless of club palette. Status colours remain consistent and always have text labels.

Every form control has a visible label. Icon-only controls have accessible names. Keep keyboard focus visible and restore focus when dialogs close. Provide empty, loading and error states. Check 320 px phone layouts and desktop layouts. Selected rounds must scope fixtures, results, standings, duties, decisions and captain reviews consistently. Constitution and account settings are explicitly season-wide or account-wide.

## Data and project boundaries

Use feature folders as features grow, services for domain I/O, and dedicated models for shared contracts. The backend sibling is ../api and its guide is ../api/CLAUDE.md. Generate API types from OpenAPI when a real API exists. Do not invent endpoints or migrations merely for a visual change.

Store fixture source, season and retrieval date alongside imported schedule data. Preserve unknown dates and times as unknown. Do not substitute another season or manufacture results. Kickoffs are absolute UTC timestamps displayed in the league's time zone (the league's `timezone`, Africa/Johannesburg by default). Competition API calls (`core/api`) use `/v1/competitions/{competitionId}/...` with `CompetitionService.current().id`. Schedule changes must not automatically change confirmed house deadlines.

## Commands and verification

From apps/web:

- npm start starts the local Angular server.
- npm run build produces the production build.
- npm test -- --watch=false runs Vitest component and logic tests.
- npm run test:e2e runs Playwright against the local server. Set PIELE_WEB_PORT when port 4200 is taken by another app, because the config reuses an existing server on that port.
- npm run test:e2e:production serves the production build with the vercel.json headers and rewrites (scripts/serve-dist.mjs) and checks deep links, 404s and the Content-Security-Policy. Run npm run build first. The CSP forbids inline scripts, so critical CSS inlining stays off; keep new code free of inline event handlers and external origins other than HTTPS API calls.

Prefer the Angular MCP for workspace discovery, best practices, builds, tests and server lifecycle when available. Consult current Angular documentation for uncertain APIs. The build must pass with no new unused-import warnings. Test changed logic and relevant browser journeys, including round scoping, profile persistence, image validation and mobile overflow. Do not claim a test passed without running it. Avoid unrelated cleanup or speculative abstractions.
