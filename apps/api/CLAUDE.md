## Session handoffs

Before starting work, read the latest Markdown handoff in [../../../handoff/](../../../handoff/), selected by the timestamp in its filename. Before ending each session, write a new handoff there named `YYYY-MM-DD_HH-mm-ss_<feature>.md`, using Africa/Johannesburg local time and a short kebab-case feature name. Record the request, completed changes, relevant files, checks actually run and their results, unresolved issues and next steps. Distinguish completed work from proposed work. Preserve previous handoffs and never include secrets.

## Project and current state

The Pavilion administers private URC leagues (it was called Piele until September 2026; Piele is now the name of its first league). Environment variables (`PIELE_*`), the `piele` schema and the `piele_api` role keep their names. The authoritative implementation plan is ../../../piele-application-plan.md relative to this directory. User decisions take precedence over proposed defaults. This directory holds a uv-managed FastAPI service: app/main.py (Vercel entrypoint, /v1 routes, exact-origin CORS, X-Request-ID and Cache-Control: no-store middleware), app/config.py (pydantic-settings), app/db.py (lazy SQLAlchemy/psycopg engine for the Supabase transaction pooler), GET /v1/health, and the competition routes under /v1/competitions/{competitionId} (app/routers/matches.py: matches/{fixtureId}, matches/{fixtureId}/preview, rounds/{round}/scores, rounds/{round}/updates; an unknown competition is 404 `unknown_competition`). Competitions live in app/competitions: `__init__.py` is the registry (`ALL`, `get(competition_id)` raising KeyError, `DEFAULT_COMPETITION_ID`); base.py holds the `Competition` dataclass (id, name, short_name, display timezone, regular_rounds, last_round, `round_label(n)`, `schedule()` loaded once per competition, `club(id)`, `clubs`, `stadium(name)`, `first_kickoff(n)`, `validate_round(n)` raising 422 `unknown_round`) and the `ScoresProvider`, `TeamsheetsProvider` and `FallbackScoresProvider` protocols; urc_2026_27/ holds the URC instance with its schedule.json (written by apps/web/scripts/import-urc.mjs), catalogue.py (clubs, stadiums) and providers.py (wiring only). Add a rugby competition as one new folder; rugby rules (shirts, timeline, weather) stay shared. The match centre lives in app/matchcentre: the schedule loader (schedule.py, parameterised by file), one `MatchCentreService` per competition in `app.state.match_centres` keyed by competition id, a read-through snapshot cache with keys prefixed `{competition_id}:` backed by the `piele.external_snapshots` table or process memory without a database, and providers for URC teamsheets, URC live scores (app/matchcentre/providers/scores.py) with an ESPN scoreboard fallback (providers/espn.py) and Open-Meteo. The URC lineup query is unverified against the live feed. Match previews live in app/agent: auth.py checks the preview agent's bearer token (`PIELE_AGENT_TOKEN`, constant-time, separate from member auth); state.py builds a fixture's deterministic inputs (teamsheets, changes from the previous teamsheet, regular starters missing, ages, bench split, rest days, travel, forecast, hashes); previews.py mirrors `piele.match_previews` (append-only revisions per competition and fixture, competition data shared by every league) and `piele.preview_dispatches`, and holds the due rule (one preview per fixture, once both teamsheets are published) and the dispatch claims (a 45-minute lease, at most 3 claims per fixture); models.py is the preview contract. app/routers/agent.py exposes `/v1/agent/*`; every agent request naming a fixture takes an optional `competitionId` (default `urc-2026-27`) that dispatches, fixture states and stored previews echo. Members of a league on the competition (or the admin, `competition_member_dependency`) read `GET /v1/competitions/{competitionId}/matches/{fixtureId}/preview`. The agent itself is the eve project in ../agent (see its README). Jev, Machine picks and results entry (plan handoff 2026-09-25_09-43-10, Phases A, D and E) are not built yet.

The league domain lives in app/league. There are several leagues: an account (`piele.users`, with the account-wide photo, the operator-set `is_admin` flag and `last_league_id`) holds at most one membership per league, and league-scoped routes carry the league in the path (`/v1/leagues/{leagueId}/...`, app/routers/league.py); the account routes are `GET /v1/me` and `GET`/`POST /v1/join/{code}` (app/routers/account.py). auth.py verifies Supabase access tokens (JWKS, or the legacy secret when configured); context.py resolves the caller inside one transaction per request, setting transaction-local `piele.auth_subject`, `piele.auth_email` and (after the checks) `piele.league_id` for row level security: `account_dependency` (a verified sign-in, no league), `actor_dependency` (the path league: 404 `unknown_league` when missing or archived, 403 `not_a_member` without an active membership unless the caller is the admin, who gets an actor with `membership_id = None` and `display_name` "Admin"), `steward_dependency` (captain or admin, else 403 `captain_only`) and `competition_member_dependency` (a member of a league on the path competition, or the admin). The `Actor` carries the league (`league_slug`, `league_timezone`, emblem and accent colour), `is_captain`, `is_admin`, `administers` (captain or admin), the membership's `favourite_team_id` and `competition`, resolved from `seasons.competition_id` with `competitions.get`; round bounds, round labels and default spoon deadlines come from it, and routers/league.py checks rounds with `actor.competition.validate_round`. Service functions that record a member as creator, recorder, submitter or decider call `require_membership(actor)`, which is 409 `admin_not_a_member` for the admin without a membership; `service.record` then writes audit events with `actor_label = 'admin'` and no actor membership. `GET /v1/me` first claims every name reserved for the verified email in every league (`service.account_leagues`); `/v1/join/{code}` reads the league its code names through the `leagues_join_code` policy (transaction-local `piele.join_code`) and claims an unclaimed name there, copying the favourite team from the account's membership on the same competition; the captain or admin can release a wrong claim. The captain or admin also removes members (`POST .../members/{id}/withdraw` with a reason: the league membership and its active season membership are withdrawn, live duties voided with "Member withdrawn", records kept, `member_left` feed entry; an unclaimed name with no records is deleted outright, falling back to a withdrawal when any foreign key still points at it; 409 `captain_membership`, `own_membership`, `already_withdrawn`) and reinstates them (`.../reinstate`, a new season membership for the active season because `season_memberships` allows one active row per member and season, 20260926170000_emblems_withdrawals.sql; 409 `not_withdrawn`). Withdrawn members are left out of `/members` (unless the steward asks `?include=withdrawn`), standings, duties, marks and the join list, and their next league request is 403 `not_a_member`; standings are recorded by member, so a reinstated member's earlier rows (on the withdrawn season membership) are updated rather than duplicated. League appearance: `emblem_path` is `preset:<key>` (`service.EMBLEM_PRESETS`: oak, anvil, lantern, compass, chevron, crown, wave, star) or an upload under `emblems/<league id>/` in the private bucket (grant from `POST .../emblem/uploads`, saved with `PUT .../appearance`, which checks the prefix, the object and its signature and deletes a replaced upload); every league description carries `emblemPreset` and a signed `emblemUrl` (`league_emblem_url_ttl_seconds`, `league_emblem_max_bytes`). The league-scoped `me` carries `joinCode` for stewards only; `POST .../join-code/rotate` and `DELETE .../join-code` change it (audit only, the code never stored in the audit trail). tables.py mirrors supabase/migrations/20260924160000_league_foundation.sql and later migrations (users, leagues, league_memberships with the per-league favourite_team_id and notification read state, seasons, season_memberships, duties, round_standings, media_assets, evidence_submissions, duty_evidence_links, feed_entries, audit_events) with SQLAlchemy Core; the users columns favourite_team_id and notifications_read_* are left in the database for one release and never read. marks.py is the authoritative house-mark calculation; storage.py issues Supabase Storage upload grants, playback URLs, prefix reads and deletes with the service role key (REST shapes unverified against a live bucket); service.py holds the domain operations, each writing its audit event and feed entry in the actor's transaction, and `create_league` (league, memberships, captain reservation, first season on a competition, a join code), shared by bootstrap.py (the operator command, `--slug`, `--name`, `--competition`, refusing a taken slug) and the planned admin endpoint. Members save their own favourite team for the league and their photo (`PUT /v1/leagues/{leagueId}/me/profile`); photos are uploaded to `avatars/<user id>/` in the private bucket with a grant from `POST /v1/leagues/{leagueId}/me/photo/uploads`, checked for size and JPEG signature, and the replaced photo is deleted. User decisions recorded in this build: Spoon duties default to the next round's first kickoff; a member's accepted evidence completes the duty at submission time, while evidence the captain records for a member completes it at the captain-entered time; the captain cannot decide evidence for their own duties; challenges never pause accrual, and a challenge resolved in the member's favour restarts the overdue clock (`duties.clock_reset_at`, `POST /v1/leagues/{leagueId}/duties/{id}/reset-clock`); Spoon duties from the future Superbru sync will be proposed for captain confirmation, not created automatically. These decisions are recorded at the end of the plan. The notifications panel reads `GET /v1/competitions/{competitionId}/rounds/{round}/updates` (app/matchcentre/updates.py: teamsheets, previews, kick-offs and full time from the cached snapshots, the stored previews and `piele.fixture_milestones`, the append-only first-seen times per competition and fixture in app/matchcentre/milestones.py) and saves what the member has read through `PUT /v1/leagues/{leagueId}/me/notifications` (a high-water mark and exception keys on the membership, merged so the mark never moves back). Superbru round standings are recorded by the captain or admin (`PUT /v1/leagues/{leagueId}/rounds/{round}/standings`, `piele.round_standings`, ranks derived on read); the Superbru sync is not built. Cases, voting, invitations by token, captain transfer, a member-initiated leave route and the admin endpoints (`/v1/admin/...`) are not built. Do not claim otherwise. See README.md for local run, bootstrap, Supabase and Vercel setup.

## Planned stack and structure

Use Python FastAPI, Pydantic request/response models, SQLAlchemy and Psycopg with Supabase PostgreSQL. Schema changes are SQL files in the repository root's supabase/migrations/, applied by the Supabase GitHub integration (user decision, superseding the plan's Alembic default). Vercel runs bounded stateless API functions. Supabase Auth and private Storage are proposed services in the plan. Do not carry over Angular, Firebase or CtrlFleet microservice conventions from the source guide.

Use app/ for application code, thin route handlers, domain services for business rules, ../../supabase/migrations/ for the single migration history and tests/ for domain, authorization and database integration coverage. APIs live under /v1. Define explicit typed contracts and generate frontend client types from OpenAPI. Use readable validation errors and request IDs without exposing private payloads.

## Non-negotiable rules

1. Validate identity and active membership in the path league on every domain request; the only exception is the global admin (`users.is_admin`, set by an operator with SQL, never by the API), who reads every league and needs a membership for writes attributed to a member. Verify token signature, issuer, audience and expiry. Never trust client-supplied roles, user IDs or league ownership.
2. Captain authority comes from the league's single captain membership (captain routes also accept the admin). Transfer requires the recipient's acceptance in a transaction. Do not use a mutable role field as a substitute.
3. Use explicit transactions, database constraints, optimistic versions and idempotency where mutations can race. Keep route handlers thin and business logic testable.
4. Use a restricted runtime database role and league-scoped RLS. Set verified transaction-local actor context so pooled connections do not leak identity. Runtime and migration credentials are separate; the API holds no migration credential.
5. Keep secrets in server configuration. Never emit tokens, signed media URLs, raw ballots or credentials in logs. Sensitive responses are not publicly cached.
6. Persist authoritative state in PostgreSQL and private Storage, never process memory or the function filesystem. Use durable jobs with leases and bounded retries, not in-process background tasks for required work.
7. Media bytes bypass the API using narrowly scoped upload grants after ownership checks. Validate actual media type and size. Profile photos require ownership checks and replacement cleanup. Do not make private member media public.
8. Profile updates affect only the authenticated user. Validate favourite_team_id against the competition team catalogue. Return safe display metadata and authorized avatar references. Do not trust client MIME claims or arbitrary remote photo URLs.
9. Persist fixture source, external ID, season and retrieval time. Import idempotently and preserve last known good data on partial failure. Keep unknown dates and kickoffs nullable. Public fixture imports do not grant access to Superbru accounts.
10. Store timestamps in UTC and display league time explicitly. A fixture reschedule cannot silently change a captain-confirmed house deadline or existing duty.
11. Superbru points and house marks remain separate. Pending constitutional interpretations are not enforceable rules. Voluntary participation cannot trigger default marks.
12. Keep audit records append-only. Ballot choices remain private. Retain only authorized media and apply the plan's season-closure retention workflow when that feature exists.
13. Do not add unrelated frameworks, speculative abstractions, services or schema. Do not deploy or use production credentials as part of local implementation.

## Configuration and verification

Configure exact CORS origins. Use a small runtime connection pool with the Supabase transaction pooler, disable prepared statements where required and verify TLS. Never run migrations on every request or function startup; the Supabase integration applies them on push. Keep application tables in the private `piele` schema, never exposed through the Data API.

Dependencies are exact-pinned in pyproject.toml with a committed uv.lock. Run tests with `uv run pytest` from this directory and the app with `uv run uvicorn app.main:app --reload --port 8000`. Use pytest for domain logic, authorization, transaction races and real PostgreSQL integration tests as those features are built. tests/test_database.py runs when PIELE_TEST_DATABASE_URL points at a database with supabase/migrations applied, connected as the restricted `piele_api` runtime role; CI does this against PostgreSQL 17. New tables in `piele` inherit the runtime grants through default privileges but still need RLS enabled and explicit policies for `piele_api`. With ENVIRONMENT=production the settings refuse to start without HTTPS CORS origins and DATABASE_URL, and the interactive docs are off. Verify OpenAPI contracts with the Angular client. Test cross-league denial, profile ownership, import completeness, timezone boundaries and failed-storage behaviour relevant to the change. Record actual commands and outcomes rather than claiming unrun checks passed.

Frontend guidance lives at ../web/CLAUDE.md. Shared contract changes must be reflected in both applications. Scope work to the user's request and preserve reversible local work.
